Search Engine Performance

Measure first

The benchmark command compares brute-force document scanning with inverted-index retrieval on the same corpus and queries, reporting per-query latency for both. Only after such measurements do optimizations earn their place: contiguous posting lists, reserved hash capacity, and serialization that loads in one pass.

Latency budget

A keyword search over thousands of documents should complete in well under a millisecond: one hash lookup per term, a posting list scan bounded by document frequency, and a small heap for the top results. The expensive parts of a real search page - snippets and metadata reads - are exactly what the benchmark keeps visible instead of hiding.
