How Search Engines Work

The pipeline

A web search engine is a pipeline. A crawler discovers and downloads pages. A parser turns raw HTML into clean text and links. A text processor tokenizes that text into terms. An indexer builds the data structures that map terms to documents. A query processor evaluates user queries against those structures, and a ranking function scores the matching documents so the best answers appear first.

MiniSearch implements this entire pipeline from scratch in C++: the inverted index, the TF-IDF and BM25 ranking functions, the Boolean and phrase query processing, and the crawler are all hand-written.

Why ranking matters

Retrieval without ranking is a sorted list of everything that matches. Ranking is what turns a match set into an answer. Classical ranking functions combine how often a term appears in a document (term frequency) with how rare the term is across the whole collection (inverse document frequency).

Modern engines add hundreds of signals, but TF-IDF and BM25 remain the readable, teachable core of text ranking, and they remain competitive baselines for keyword search.
