The Inverted Index

From documents to terms

An inverted index maps every term to the list of documents that contain it, together with term frequencies and word positions. With three documents - one about C++ programming, one about Python programming and one about competitive programming in C++ - the term programming points at all three documents, while python points at only one.

Because posting lists are sorted by document id, Boolean operations become cheap two-pointer merges: intersection for AND, union for OR, and subtraction for NOT.

Positions enable phrases

Storing the position of every occurrence makes exact phrase search possible. To match the phrase competitive programming, the engine checks whether the two terms appear in adjacent positions in the correct order within the same field of a document.

MiniSearch stores a virtual position stream per document that spans title, headings and body, with deliberate gaps at field boundaries so a phrase can never falsely match across two different fields.

Complexity

Looking up one term costs one hash lookup plus a scan of its posting list: proportional to the number of documents containing the term, not to the total collection size. Brute-force scanning instead touches every document for every query; the benchmark command in MiniSearch measures the difference on real data.
